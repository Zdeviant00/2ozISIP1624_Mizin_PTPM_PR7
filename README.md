**Цель работы:** Приобрести практические навыки юнит-тестирования разработанного приложения с использованием средств автоматизации Microsoft Visual Studio методом «белого ящика».

## 📌 Описание
Реализация класса `BankAccount` с методами:
- `Debit` — списание средств со счёта
- `Credit` — пополнение счёта

## 📋 Ход работы

### ✅ Этап 1: Анализ исходного кода и обнаружение ошибок

При первоначальном запуске приложения обнаружены следующие проблемы:

#### 🔴 Баг №1: Логическая ошибка в методе `Debit`
**Описание:** Метод `Debit` использует оператор `+=` вместо `-=` для уменьшения баланса.

**Код с ошибкой:**
```csharp
public void Debit(double amount)
{
    // ... проверки ...
    m_balance += amount; // ❌ Ошибка: должно быть -=
}
```
![Запуск](https://github.com/user-attachments/assets/87fa1603-c62e-4db2-b3df-87a89004f0cf)

#### ⚠️ Замечание №1: Использование типа `double` для финансовых операций
**Описание:** В коде используется тип `double` для хранения баланса счёта. Однако тип `double` реализует арифметику с плавающей точкой в двоичном формате, что приводит к накоплению погрешностей при операциях с десятичными дробями.

**Проблема:**  
Результат операций отображается как `$28.979999999999997` вместо ожидаемого `$28.98`. Это происходит потому, что десятичные дроби вроде `0.1`, `0.01` не могут быть точно представлены в двоичной системе.

### 🔧 Этап 2: Подготовка к тестированию (рефакторинг)
Проведён рефакторинг для **устранения хардкодинга** и обеспечения удобного ручного тестирования:

1. **Замена типа `double` → `decimal`**  
   - Обеспечивает точное отображение денежных значений (`$6.54` вместо `$6.539999999999999`)

2. **Интерактивный ввод тестовых данных через консоль**  
   - Все параметры (начальный баланс, суммы операций) вводятся пользователем при запуске
   - Исключения перехватываются и отображаются в консоли (приложение не падает)
